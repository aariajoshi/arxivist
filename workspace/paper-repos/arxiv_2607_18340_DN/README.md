# Quantum Cryptanalysis on IBM Quantum Hardware — ArXivist Reproduction

Reproduction generated by **ArXivist** from:

> Kim, T., Hong, Y., Kim, M., Choi, S., Jang, J., Shin, J., Kim, M.
> *Quantum Cryptanalysis on IBM Quantum Hardware: Extending Even-Mansour
> Period Recovery from N=4 to N=10.* arXiv:2607.18340 (2026).

Implements five genuine (un-compiled) quantum attacks on toy/reduced
symmetric-cipher structures — **Bernstein-Vazirani**, **Grover** (SPN key
search), and **Simon's algorithm** applied to **Even-Mansour**, **CBC-MAC
forgery**, and **3-round Feistel** — using Qiskit.

## ⚠️ Read this first: what this repo can and can't reproduce

**The paper's headline real-hardware result (Even-Mansour recovery at
N=6–10) depends on a technique the paper explicitly withholds** pending an
IP decision (Section 5, Supplementary S4):

> "Achieving clean period recovery at the reported noise levels and
> structure sizes additionally relies on a hardware-aware circuit-
> conditioning and readout post-selection technique. The full specification
> of that technique is withheld in this draft..."

**This cannot be reproduced from the paper as written.** This repo instead:
- Faithfully implements the five **disclosed** algorithms exactly as specified.
- Defaults to a **noiseless Qiskit Aer simulator**, where these textbook algorithms recover periods/secrets cleanly (rank-1) by construction — **16/16 clean recoveries** across all validated sizes in this repo's test suite.
- Includes a clearly-labeled **best-effort substitute** (`TopKHybridRanker`) for experimenting with a noisy backend — explicitly NOT the paper's real method, and it performs poorly by design (it's not tuned to be good — see its docstring).
- Does not have access to real IBM hardware (`ibm_kingston`); a real-backend hook exists via `qiskit-ibm-runtime` if you have your own IBM Quantum credentials.

## Verified findings from implementation (not just SIR-level assumptions)

Building and testing this repo surfaced two concrete, testable discoveries
beyond the SIR's parsing-stage ambiguities:

1. **A naive single-permutation-call Even-Mansour oracle is mathematically
   wrong.** `f(x) = P(x XOR k1)` is a *bijection* (since P is a permutation
   and XOR-by-constant is a bijection), so it cannot hide a period — Simon's
   algorithm requires a genuinely 2-to-1 function. The correct
   Kuwakado-Morii construction is `g(x) = P(x XOR k1) XOR P(x)`, which
   *is* provably 2-to-1 with period k1. This is standard textbook material
   the paper assumes but doesn't spell out; `oracles/simon_even_mansour.py`
   documents the derivation in full.
2. **The paper's stated CBC-MAC-forgery period formula appears to be
   wrong.** The paper states `f(x) = Ek(x XOR c.a) XOR Ek(x XOR c.b)` has
   period `s = Ek(a) XOR Ek(b)`. Direct testing shows this oracle instead
   satisfies Simon's 2-to-1 promise with period **`s = a XOR b`** (the
   *input*-space difference) — by the same algebraic identity used for
   Even-Mansour. The paper's formula was verified NOT to satisfy the
   promise for generic test permutations. See
   `oracles/simon_cbc_mac.py` and `comparison/hallucination_report.md` for
   the full writeup.
3. **Random permutations don't scale as Even-Mansour/CBC-MAC test
   instances.** A uniformly-random permutation P satisfies Simon's strict
   2-to-1 promise with rapidly-vanishing probability as n grows (a
   birthday-paradox-like effect over the 2^(n-1) coset pairs that must all
   map to distinct values). `oracles/simon_even_mansour.py::find_valid_permutation`
   uses a deterministic greedy construction instead of random search, and
   reliably succeeds up to n=10+.
4. **Grover key search can have multiple valid keys for one known
   plaintext/ciphertext pair** (key→ciphertext at fixed plaintext need not
   be injective), which is a real cryptographic property, not a bug — when
   it happens, Grover correctly returns *a* valid key, just not necessarily
   the specific "true" one used to generate the demo instance.
   `algorithms/grover_circuit.py` corrects the iteration count for M>1
   marked items; `run_attack.py`'s demo additionally picks unambiguous
   instances so its reported success rate reflects Grover's own
   correctness rather than this cipher-design artifact.

## Other assumptions (see SIR for full detail)

- **Shot counts** default to 4096 (paper's actual per-job values are
  unrecoverable `[measurement]` placeholders in the provided PDF).
- **Grover's target SPN** (`oracles/grover_spn.py::ToySPNCipher`) is a
  small, clearly-labeled stand-in — the paper never specifies its
  S-box/rounds/key schedule.
- **Readout mitigation** (`backend/mitigation.py`) implements only the
  standard, published technique (Nation et al.) — not the paper's withheld
  hardware-specific method.
